# Gerber Cost Estimator

Автоматизированная система оценки стоимости изготовления печатных плат на основе анализа Gerber-файлов. Приложение позволяет инженеру-разработчику мгновенно получить расчёт цены прямо из конструкторской документации, а производителю — гибко настраивать собственные тарифные сетки через API.

## Ключевые возможности

- **Загрузка ZIP-архива** с Gerber- и Excellon-файлами – никакого ручного ввода параметров.
- **Автоматическое распознавание слоёв** (медь, маска, шелкография, контур, сверловка) по метаданным Gerber X2, стандартным расширениям и ключевым словам в именах файлов.
- **Геометрический анализ**:
  - минимальная ширина проводника;
  - минимальный зазор между электрическими цепями (на базе вычислительной геометрии JTS).
- **Анализ отверстий**: определение количества, диаметров, типа металлизации, наличия глухих/скрытых переходных отверстий.
- **Визуализация** всех слоёв платы (через интеграцию Delta Gerber + JavaFX).
- **Расчёт стоимости** с учётом тарифов выбранного производителя, технологических ограничений и надбавок.
- **Сравнение предложений** разных заводов, подключённых через API.
- **Экспорт детализированной сметы** в PDF.

## Архитектура (кратко)

Проект состоит из двух логических частей:

1. **Десктопный клиент** (JavaFX) – загрузка Gerber-файлов, их парсинг, визуализация платы и взаимодействие с пользователем. Модуль парсера работает полностью локально и не требует сети.
2. **Серверная часть** (Spring Boot) – REST API для хранения тарифов производителей, технологических ограничений и выполнения расчёта стоимости. Клиент отправляет на сервер извлечённые параметры платы и получает готовую смету.

Такое разделение позволяет использовать приложение как независимый Pre-CAM инструмент, не привязанный к конкретной САПР или производителю.

## Модуль парсера Gerber-файлов

Сердце проекта – модуль `com.diplom.gerber`. Он принимает на вход ZIP-архив с Gerber- и Excellon-файлами и формирует объект `BoardParameters`, содержащий все необходимые для оценки параметры платы.

### Основной сервис: `GerberFileParser`

Главный координатор парсинга. Его метод `parseFromZip(InputStream zipStream)` выполняет следующие шаги:

1. **Извлечение файлов** из ZIP-архива с сохранением оригинальных имён (метод `extractZipEntries`).
2. **Параллельная обработка** каждого файла:
   - Если файл является Gerber-слоем – вызывается `parseGerberLayer`, который:
     - парсит содержимое с помощью `GerberParser` (Delta Gerber);
     - классифицирует слой через `LayerClassifier`;
     - вычисляет границы слоя (`BoundingBox`);
     - для медных слоёв запускает `GeometryAnalyzer` для расчёта минимальной ширины дорожки и минимального зазора.
   - Если файл определён как сверловка (по расширению `.drl`, `.txt` и т.п.) – задействуется `DrillAnalyzer`:
     - парсит Excellon-данные;
     - извлекает координаты и диаметры отверстий;
     - определяет тип металлизации (PTH/NPTH) и наличие глухих/скрытых переходных отверстий;
     - создаёт специальный слой с типом `DRILL` для последующей визуализации.
3. **Сборка итоговой модели** `BoardParameters`:
   - габариты платы (по контуру `OUTLINE` или объединению границ всех слоёв);
   - количество медных слоёв, слоёв маски и шелкографии;
   - агрегированные минимальная ширина проводника и минимальный зазор (по всем медным слоям);
   - статистика отверстий: общее количество, количество металлизированных, минимальный диаметр, наличие глухих/скрытых переходов.

### Классификатор слоёв: `LayerClassifier`

Определяет тип и сторону слоя по цепочке приоритетов:
- **Метаданные Gerber X2** (атрибут `FileFunction`) – например, `Copper,L1,Top` однозначно задаёт медный верхний слой.
- **Стандартные расширения** (`.GTL`, `.GBL`, `.GTS`, `.GKO` и др.) в соответствии с общепринятыми соглашениями САПР.
- **Ключевые слова в имени файла** (для нестандартных расширений) – `COPPER_TOP`, `SOLDERMASK_BOTTOM`, `OUTLINE` и т.п.

Такой трёхуровневый подход гарантирует корректную классификацию проектов, созданных в Altium, KiCad, Eagle и других системах.

### Анализатор геометрии: `GeometryAnalyzer`

Выполняет две ключевые метрики, критически влияющие на стоимость изготовления:

- **Минимальная ширина проводника** (`computeMinTrackWidth`) – определяется как наименьший характерный размер апертуры (диаметр окружности, ширина прямоугольника/овала) среди всех зарегистрированных апертур слоя.
- **Минимальный зазор** (`computeMinClearance`) – реализован с использованием библиотеки **JTS (Java Topology Suite)**:
  1. Все графические объекты слоя (Flash, Draw, Arc, Region) преобразуются в точные JTS-геометрии с учётом апертур.
  2. Выполняется кластеризация объектов по электрическому контакту (алгоритм Union-Find): пересекающиеся геометрии объединяются в одну цепь.
  3. Для каждой пары различных кластеров вычисляется расстояние (`distance`) – минимальный зазор между цепями.
  4. Наименьшее найденное расстояние возвращается как минимальный зазор слоя.

Использование JTS позволяет получить высокую точность, сопоставимую с промышленными CAM-системами.

### Анализатор сверловки: `DrillAnalyzer`

- Проверяет принадлежность файла к формату Excellon по расширению.
- Извлекает отверстия: координаты центра, диаметр (из инструмента `Tool`) и тип металлизации (определяется по комментариям в файле или ключевым словам `PTH`/`NPTH` в имени).
- Определяет наличие глухих (`BLIND`) и скрытых (`BURIED`) переходных отверстий по комментариям и паттернам типа `L1-L2`.

### Модель результата: `ParseResult`

Возвращает:
- `BoardParameters` – полностью заполненную модель платы (размеры, слои, отверстия, мин. зазоры и пр.).
- `Map<BoardLayer, Object>` – для каждого слоя сохраняется оригинальный документ (`GerberDocument` или `DrillDocument`), который затем используется модулем визуализации.
